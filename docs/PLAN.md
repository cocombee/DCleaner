See the parity ledger in this plan for unsupported sections and verification gaps.

## Build and run

Requires Rust stable and native platform build tools. On Windows, install Microsoft C++ Build Tools and a Windows SDK, then:

```powershell
./scripts/build.ps1 -Action test
./scripts/build.ps1 -Action build -Release
./scripts/install.ps1 -SourceExecutable ./target/release/dcleaner.exe
```

The canonical Windows executable is `%LOCALAPPDATA%/Programs/DCleaner/DCleaner.exe`, with one Start menu shortcut. The installer replaces that file after checking the build hash and leaves data intact. A session mutex prevents duplicate interactive launches across build paths. Native installation and second-launch checks passed: second launch exited with code 0 and one canonical interactive process remained. This does not establish macOS installation. `cargo run --locked` is a development command; avoid leaving development copies running beside the installed app. `--scan-json` performs a read-only diagnostic scan. Set `DCLEANER_DATA_DIR` only for isolated QA; normal runs use the user's OS application-data directory. References, user data, analysis reports and build output are excluded from Git.

## User guide

- Start an analysis to inspect supported files. Review current results and confirm the selected action before cleaning; a saved advanced option does not establish that its effect is supported.
- Supported file cleanup uses the system Trash or Recycle Bin. Review Cleanup History for confirmed, failed and uncertain outcomes. An uncertain operation is not permission to retry it automatically.
- Startup Manager reads current startup/task/service/context entries. Review each proposed change; inaccessible or unsupported entries stay read-only.
- Software and Driver Updater show source and identity limitations. Review the exact offered update and backup/restore requirements. Starting an installer is not verification that an update completed.
- Performance Optimizer's Applications catalogue supports review and exclusions. Excluding an app does not stop it. Active/Sleeping classification, measured impact and native Sleep/Wake remain unavailable until the background owner is implemented and verified.
- Help links use the default browser. Review local diagnostics before saving or sharing them; reports are not uploaded by the app. Choose a new filename for an export so existing reports remain unchanged.
- Cloud Drive Cleaner has one provider Connect entry, account switching/disconnect, scan/cancel, large/possible-duplicate/older/ignored views, per-row review, selected-trash review and paged cleanup/restore history. History remains reachable with no connected account. Trash is reviewed in batches of up to 200 items; unknown or interrupted outcomes are never retried automatically. Folders remain read-only pending descendant-aware review. OneDrive work/school restore is unavailable through the documented Personal restore API. Provider retention and trash quota rules still apply.
- This build has no supplied DCleaner-owned provider credentials. Connect reports that sign-in is unavailable; it does not fabricate an account or reuse CCleaner's credentials. There is no registration wizard in the user-facing app. App-owned OAuth provisioning and real account acceptance remain implementation gates.

Native visual acceptance and full CCleaner parity remain open in the ledger above. macOS plans and compiler checks do not establish macOS feature/runtime acceptance.
